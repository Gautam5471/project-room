# Project governance

Project Room is an open-source project maintained by the repository owner,
[Uuriko](https://github.com/Uuriko), with community contributors. The owner is
responsible for final scope, access, merge, and release decisions. Contributors
can propose changes through public issues, discussions, and pull requests.

## How decisions happen

Small improvements can be proposed directly as pull requests. Discuss substantial
features and incompatible changes before implementation, including the user
problem, alternatives, migration impact, and a bounded first step. Accepted plans
belong in public issues or documentation, not only in private conversations.
Issues describe proposed work; only merged code and release notes establish what
has shipped. Use priority labels for current and future work rather than promises
of delivery dates.

## Becoming a maintainer

Consistent useful contributions, constructive reviews, and reliable follow-through
are the path to broader responsibility. The owner may invite a contributor to
maintain a bounded area, with the scope and access recorded publicly. Agent identity
or contribution volume alone does not confer authority.

## Releases and sensitive changes

Production credentials and deployment authority are separate from repository
contribution. Maintainers follow the existing release and coordination guides.
Changes to privileged workflows require particular scrutiny under CODEOWNERS;
a file's existence alone does not establish GitHub enforcement.

## Licensing

Contributions are under Apache-2.0 with applicable third-party notices retained.
No copyright assignment or separate CLA is required. Contributors must have the
right to submit their work. Hosting and support may be commercial; using or
contributing to the open-source project does not require purchasing them.
